# Qwen 统一筛选流程 standard_v2

此版本用于后续诊断、检查、治疗三个任务的 UPDATE / MAINTAIN 筛选。
历史结果保留，旧版通过数量不自动转为新版正式通过数量。

## 顺序与门槛

1. 检查原题和 gold 是否齐全；分类是否属于患者层面的临床判断。分类有疑问可人工覆盖。
2. **原始完整题独立作答 3 次，正确至少 2 次后才允许构造证据切分。** 答题输入没有 gold、解析或 key points。
3. 复用能严格映射回原题的人工切分，否则自动提出至多两个方案。每个方案至多 4 个证据组，每组可包含多个原题片段。不新增事实、不改变原题任务。机器检查精确来源；临床连贯性和任务保真仍需人工复核。
4. E1 与 E1＋全部 K 各 3 次开发检查；从实际回答冻结 A。再各独立 5 次，至少 4/5 符合预期。
5. UPDATE：按证据组数从小到大枚举组合，每个组合测 5 次。找到最小达到 4/5 的组数，并在同组数候选中选择字数最少者。最小性只针对这组预设证据单元，不声称全局最小或确定的因果关系。完整 K 通过的结果始终保留。MAINTAIN 不搜索“触发变化的最小 K”，保留相关但非决定性的 K。
6. 冻结选中的 K 后，E1 和 Fresh 再各独立 5 次、至少 4/5。选择 K 时的回答不复用作最终验证。未通过则保留历史通过记录，但不进入正式行为实验。
7. 用完全相同 E1/K 做 Fresh、Sequential、固定 prior label，各 5 次。Sequential 保留真实初次输出；固定 prior 与 Fresh 仅相差 prior 文本。记录首选答案、确定性和最初是否确为 A。
8. 分别统计正常更新、保持、坚持旧判断、不确定、其他待复核。出现一次差异不自动认证为稳定错误。

## 语义评分与人工复核

默认只有规范化后的完整 gold 字符串相等才自动识别 B；绝不以疾病关键词子串充当等价判断。
非精确匹配进入 `review_queue.json`，**不等于已判错**。可以在 `reviews.json` 增加经过审阅的同义词或逐回答判定，再重跑相同任务；已保存的模型回答不会重新调用。

- `sources[源记录 SHA256]`：`reviewed: true`、`gold_aliases`、`alternative_aliases`，可选 `eligibility`。
- `answers[review_queue 的键]`：`reviewed: true`、`label`（`B`、`A:规范化名称`、`OTHER`、`UNCERTAIN`）。
- `cases[case_sha256]`：`approved: true`、`selected_K_indices`，以及审阅备注。审批必须针对确切刺激材料和选中的 K。

未复核的替代答案可用于探索性构造 A，但不能直接当成医学上已确认的错误。命名首选答案与 `differential` 状态分开记录。正式导出的病例需要临床审核通过；不能仅用自动评分结果做金标准。

## 运行、恢复与审计

`prepare.py` 准备全部有非空原题和答案的数据；无答案条目保留在覆盖清单中。人工构造和自动发现共用 `Pipeline.run_case`，不存在绕过原题门槛的独立入口。

`runner.py` 每个任务处理一个原题，要求 2 张 A40。同一原题的原始答题门槛仅跑一次。生成缓存校验完整消息、模型路径、采样参数和种子。截断输出、解析失败、超出长度/预算均不当成通过。中断保存已完成内容，不伪装成完整完成。

本版本显式设置 top_p=1、top_k=0，并使用统一的任务保真提示词，因此旧版生成配置不完全相同；旧缓存仅作历史证据，不用于绕过新版门槛。

恢复前确认同源任务不再运行；硬杀死可能留下 `active.lock`，应核对锁里的作业号已结束后再移除。修正语义审核后重新执行同一索引，会复用已完成调用并重算门槛。未通过语义门槛的条目要先复核，不能盲目重复生成。

准备脚本不提交 GPU 作业；`run.sbatch` 也不默认附带全量数组，避免误发全量重跑。由实际需要补验的源记录选择索引后提交。

验证：`python -m unittest discover -s . -p 'test_*.py' -v`。测试使用模拟响应，不代表真实 Qwen 已完成新版验证。
